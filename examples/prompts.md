4교시 실습에서 Code 탭에 보내는 문장을 순서대로 모았어요. 인터뷰, 설계, 승인, 화면 연결, PRD와 비교 문장은 강사가 리허설에서 실제로 보내서 통한 문장이에요. 커밋은 리허설 때 강사가 git으로 직접 했고, 실습 1의 커밋 문장과 8081 문장은 검토 때 따로 보내서 통했어요. 그대로 써도 되고 내 말로 바꿔도 돼요. 〔 〕로 표시한 곳이 내 것으로 바꿀 곳이에요. 〔 〕 기호는 보내지 않아요.

같은 폴더에 실제로 나온 결과도 있어요.

| 파일 | 무엇 |
| --- | --- |
| `PRD-praise-relay.md` | 인터뷰로 실제로 만든 PRD예요. 시간이 모자라면 내 작업 폴더에 `PRD.md`로 저장하고 주제와 칸 이름만 바꿔요 |

| `praise-relay-done.webp` | 다 만든 칭찬 릴레이 화면이에요. 서버를 껐다 켠 뒤에도 글 세 개가 그대로 있어요 |

## 따라 하기: 시작 폴더 열기 (3분)

보내는 문장은 없어요. 강사 화면을 보며 같이 해요.

1. `dbinc-ai-course/labs/guestbook/starter` 폴더를 복사해서 홈 폴더 아래 `dbinc-work`에 붙여 넣고, 이름을 〔praise-relay〕처럼 내 주제로 바꿔요.
2. Code 탭에서 **+ New session**, **Local**, **Select folder**로 그 폴더를 골라요.
3. 모드 메뉴에서 **Plan**을 골라요.
4. 입력창에 `/`를 치고 목록에 `prd-interview`가 보이는지 봐요. 아직 보내지 않아요.

## 실습 1: 인터뷰로 PRD (2절, Plan 모드)

```text
/prd-interview 〔칭찬 릴레이〕
```

질문 카드가 오면 골라요. 카드 대신 글로 물으면 번호나 내 말로 답해요. 리허설에서는 글로 물어서 아래처럼 한 번에 답했어요.

```text
1번이에요. 나머지도 한꺼번에 답할게요. 칸 이름은 〔보내는 사람, 칭찬 한마디〕. 더할 칸은 〔받는 사람(to)〕. 목록은 〔카드〕. 분위기는 〔밝고 가벼운 느낌〕. 빼는 것은 로그인, 수정·삭제, 페이지 나누기, 검색 네 개 모두예요. 다 정했으니 PRD 내용을 보여 주고 PRD.md로 써 줘. 승인할게요.
```

계획으로 나온 PRD를 읽고 **Yes, manually approve edits**로 승인해요. `PRD.md`가 생기면 커밋을 부탁해요.

```text
이 폴더를 git 저장소로 만들고 지금까지를 커밋해 줘. 메시지는 "〔칭찬 릴레이〕 PRD"로 해 줘.
```

끝나면: 작업 폴더에 `PRD.md`가 있어요. 리허설에서는 36줄이었어요(`PRD-praise-relay.md`). 커밋 문장을 보내 봤더니 11초 만에 저장소를 만들고 다섯 파일(`PRD.md`, `SKILL.md`, `index.html`, `README.md`, `.gitignore`)을 커밋했어요. 커밋 메시지 끝에 `Co-Authored-By: Claude …` 한 줄이 붙어요.

## 실습 2: 설계하고 서버까지 (3절, 새 세션, Plan 모드)

```text
@PRD.md 대로 만들 설계 계획을 세워 줘. 아직 파일은 만들지 마.
- 화면은 web 폴더에 React와 Vite로 만들어. 개발 서버는 5173이야.
- 서버는 api 폴더에 〔Spring Boot(Gradle)〕로 만들어. 포트는 〔8080〕이야.
- DB는 SQLite 파일 하나로 시작해. 파일은 api/data 폴더에 두고 Git에는 올리지 않아. JPA 같은 ORM은 쓰지 마.
- DB 주소는 application.properties의 spring.datasource.url에 적어 둬. 나중에 환경 변수로 바꿀 수 있게.
- 화면(5173)과 서버(8080)는 출처가 달라. Vite proxy로 풀지 서버에서 CORS를 허락할지 질문 카드로 물어봐. 백엔드를 Spring Boot 말고 다른 것으로 바꿀지도 같이 물어봐.
- API 약속은 PRD.md 그대로야. 확인 도구는 python3 ~/dbinc-ai-course/labs/guestbook/smoke_test.py --url http://127.0.0.1:〔8080〕 이고 이 파일은 고치지 마. ~/dbinc-ai-course 폴더의 다른 파일은 열지 마.
- 맨 위 index.html은 Python 길에서 쓰는 시작 화면이라 손대지 마.
- 개발 서버 두 개는 .claude/launch.json에 api와 web으로 적어서 Browser 창에서 켜고 끌 수 있게 해 줘.
- 단계는 1) 서버와 DB 2) 화면 연결로 나누고, 단계마다 무엇으로 확인할지 적어 줘.
- 내가 계획을 승인하면 1단계만 만들고 확인 도구 결과를 보여 준 뒤 멈춰. 실패가 있으면 고치기 전에 원인부터 말해 줘.
```

바꿀 곳: 회사에서 쓰는 다른 백엔드가 있으면 서버 줄의 이름과 포트, 확인 도구 주소의 포트를 같이 바꿔요.

Claude가 두 가지를 물어요. 리허설에서는 둘 다 추천을 골랐어요.

| 질문 | 고른 것 |
| --- | --- |
| 화면과 서버의 출처가 다른 문제를 어떻게 풀까요? | Vite proxy (추천) |
| 백엔드는 무엇으로 할까요? | Spring Boot (Gradle) 유지 (추천) |

계획을 읽고 **Yes, manually approve edits**로 승인해요. 명령 권한 카드가 뜨면 명령을 읽고 허락해요. 확인 도구가 3개 모두 ok이면 커밋을 부탁해요.

```text
커밋해 줘. 메시지는 "서버와 DB, 확인 도구 통과"로 해 줘.
```

끝나면: 확인 도구 출력의 마지막 줄이 `OK`예요(`smoke-ok.txt`). 브라우저에서 http://127.0.0.1:8080/api/entries 를 열면 JSON 목록이 보여요.

8080을 다른 프로그램이 쓰고 있으면 Claude가 멈추고 물어요. 그 프로그램이 내 것이 아니면 끄지 말고 이렇게 부탁해요.

```text
8080은 다른 프로그램이라 끄지 마. 우리 서버를 〔8081〕로 바꾸고, launch.json과 확인 도구 주소도 〔8081〕로 맞춰서 다시 검사해 줘.
```

리허설에서는 다른 프로그램이 먼저 꺼져서 8080 그대로 검사했어요. 이 문장은 검토 때 8080에 다른 프로그램을 켜 두고 따로 보내 봤어요. Claude가 세 파일의 포트를 한 줄씩 8081로 바꾸고, 8080 프로그램은 끄지 않은 채 확인 도구 3개를 통과시켰어요. 8081로 옮겼으면 실습 3의 화면 연결 요청 끝에 "proxy는 8081로 보내 줘"를 더해요.

## 실습 3: 화면 붙이기 (4절, Accept edits 모드)

같은 세션에서 이어 가도 되고, 대화가 길어졌으면 새 세션에서 보내요. 모드는 **Accept edits**로 바꿔요. 리허설도 새 세션, Accept edits 모드였어요. npm 명령은 권한 카드를 읽고 허락해요.

```text
@PRD.md를 보고 web 폴더의 React 화면을 서버에 연결해 줘. src/App.jsx의 기본 화면은 지우고 〔PRD의 화면대로〕 바꿔.
- 글은 POST /api/entries로 보내고, 목록은 GET /api/entries로 받아서 보여 줘. 설계에서 proxy를 골랐으면 주소는 /api/entries 그대로 써.
- 글은 JSX의 {값}으로만 넣고 dangerouslySetInnerHTML은 쓰지 마.
- 저장하는 동안 버튼을 막아서 두 번 눌리지 않게 하고, 서버 오류는 화면에 문장으로 보여 줘.
- 이름은 40자, 내용은 500자까지만 입력되게 하고, 비어 있으면 보내지 않게 화면에서도 막아 줘.
- 모양은 src/index.css와 src/App.css로 잡고, 다른 패키지는 추가하지 마.
- 끝나면 Browser 창에서 저장, 새로고침, 목록을 확인하고 확인 도구도 다시 돌려 줘. 확인 도구는 고치지 마. 커밋은 아직 하지 마.
```

바꿀 곳: 화면 모양은 PRD가 정해요. 목록 모양이나 분위기를 바꾸고 싶으면 이 자리에 내 말로 적어요(예: "카드 대신 한 줄 목록으로").

리허설에서는 web 폴더가 아직 없어서 Claude가 `npm create vite`로 먼저 만들고 연결했어요. 놀라지 않아도 돼요.

끝나면: Browser 창에서 글을 남기고 새로고침해도 남아 있어요. 내용에 `<b>굵게</b>`를 넣으면 태그 글자 그대로 보여요(`praise-relay-done.webp`).
